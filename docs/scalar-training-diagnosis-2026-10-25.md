# Saved scalar training: diagnosis and proposed next experiment

Prepared 2026-10-25. **Proposal only: no new training, model inference, provider operation, reservation, or audit rerun has been performed.** The completed scalar runs and their scientific conclusions remain unchanged.

The strongest finding is that twenty shared optimizer updates supplied very few informative reward contrasts for some tasks. This explains a concrete limitation of the training signal; it does not prove a single cause of the held-out result. Overall improvement remains unestablished: weighted return change −0.001143, descriptive 95% interval [−0.015030, +0.017514]. One seed and sixteen held-out families per task cannot establish general transfer.

## What the saved traces establish

The analysis uses all 20 committed production cohorts: 200 episodes, 5,978 decisions, and 20 Adam updates. Calibration is excluded. Separate [game behavior counts](/Users/mitchellcatoen/Documents/workspace/selfplay/runs/scalar-trace-diagnosis-20261025-v1/behaviors.json) and [market diagnostics](/Users/mitchellcatoen/Documents/workspace/selfplay/runs/scalar-trace-diagnosis-20261025-v1/market.json) include their input and analysis-script hashes. All three calculations use saved JSON only.

**Sparse feedback and coarse credit assignment.** Every cohort has only two independent scenarios per task. The baseline for a role is the other scenario's terminal return, and that return difference is copied to every decision in the trajectory. If both planning episodes fail, every planning reward advantage is exactly zero. This happened in 19/20 cohorts. Chess had zero reward contrast in 16/20. Entropy, KL, and changes to the shared parameters can still affect these tasks; “zero reward advantage” does not mean their model parameters were frozen. See the frozen [advantage construction](/Users/mitchellcatoen/Documents/workspace/selfplay/runs/arena-mixed-scalar-training-gpu-v1/source/selfplay/arena_mixed/cuda_policy.py:157).

This independent baseline is not an identified mathematical bug. Comparing different scenarios can add difficulty-related variance, but the saved run has no repeated rollouts of the same training scenario with which to measure that variance. Terminal Monte Carlo credit is also a legitimate estimator; it simply cannot tell a successful intermediate edit from the later edit that destroyed it within one recorded trajectory.

Coding supplies a concrete example: `train-13-coding-1` repaired its program, observed 4/4 public tests passing, edited again, and ended with zero hidden tests passing. Five training episodes reached the exact reference program during the episode and subsequently damaged it; none of those five ended fully correct. Those audit-only reference comparisons never enter the learner input. See [cohort 13](/Users/mitchellcatoen/Documents/workspace/selfplay/runs/arena-mixed-scalar-training-gpu-v1/cohorts/13/episodes.json) and the frozen [terminal coding reward](/Users/mitchellcatoen/Documents/workspace/selfplay/runs/arena-mixed-scalar-training-gpu-v1/source/selfplay/arena_mixed/coding.py:260). This is evidence of poor stopping behavior and coarse credit, not evidence that changing the reward will necessarily fix it.

**Self-play offered weak opponents and a relative market objective.** In market training, 22 of the 40 positively advantaged player trajectories still lost absolute money. Reward is relative P&L, so it can reinforce losing less than a peer. Direct interaction was real—203 units traded between the two agents—but they collectively lost 698 units of P&L to background traders. The relative objective is the declared objective, not an implementation error. It does not guarantee profitable trading. Held-out relative return also worsened, so an absolute/relative mismatch alone cannot explain the result.

The held-out maze gain occurred against frozen base: both endpoints lost all 32 maze episodes against the heuristic. Chess against the heuristic stayed at 28 draws and four checkmate losses. These observations make stronger fixed opponents a reasonable later experiment; they do not justify combining an opponent change with the first curriculum test.

**Policy updates happened, but the evidence does not support blaming PPO clipping.** All twenty updates changed the adapter. Per-step parameter-change L2 norms were 0.00426–0.01317. Global gradient clipping applied in 12/20 updates; that is separate from PPO ratio clipping. Across all 5,978 saved training rows, selected-action learner/behavior ratios were 0.98447–1.01827, and none crossed 0.8 or 1.2. Mean total-variation distance between those distributions was 0.000372. These compare the learner to its rollout behavior, usually one version earlier—not final policy to base.

There is also direct endpoint evidence of modest market movement: 55/64 held-out action sequences were identical. On 942 matching state/menu observations, mean base-to-final distribution total variation was 0.00630. A small probability change can alter a seeded sampled action and the entire following trajectory, so the few changed episodes should not be narrated as broad strategic learning.

**Do not infer gradient dominance from scalar loss values or task coefficients.** Cohort 1 has policy loss zero despite 340 nonzero advantages: signed surrogate values cancel at ratio one while derivatives need not. The entropy term's larger scalar value does not show that entropy dominated the parameter update. Task coefficients multiply sums over actions. Their accumulated action-weight shares were chess 32.0%, maze 29.5%, market 20.8%, planning 15.4%, coding 2.4%; these are not gradient shares. The numerical artifact also reports derivatives with respect to separate action logits, explicitly not shared-parameter gradients. Harmful task interference remains unmeasured.

Planning's training/evaluation depths were both balanced over 3–6, so a harder nominal evaluation depth is not the explanation. Coding coverage was uneven (training: 24 counting, 14 summation, two maximum tasks; evaluation: 13 counting, three summation, no maximum tasks). That limits the breadth of a coding claim. Only forty independent training scenarios per task and one training seed were observed. More optimization could help, but these traces do not establish that scaling the identical protocol is a good use of the next dollar.

## Recommended next experiment: planning curriculum versus current difficulty

**Question:** Does giving the same learner reachable successes before the original tasks improve held-out planning success and reduce the frequency of zero-advantage updates?

Planning is the first diagnostic because it has the clearest measurable floor: 1/40 training successes and only 17 reward-bearing decisions. Both arms are planning-only to isolate the curriculum from shared-task interference. This would test a mechanism in the larger project, not demonstrate that all five tasks improve. Starting closer to attainable goals is motivated by sparse-reward curriculum research, but its benefit for this model remains a hypothesis ([Florensa et al., 2017](https://arxiv.org/abs/1707.05300)). Easier tasks also alter the visited states and episode lengths; a positive result would support this curriculum intervention, not prove that reward sparsity was the sole cause of the original result.

The proposed design is fixed before any new policy draw:

| Item | Specification |
|---|---|
| Base/model | Same pinned Qwen3-8B NF4/LoRA and action-label interface, thinking disabled; all four runs begin from one identical freshly initialized base adapter/checkpoint and zero-step Adam, not the completed cycle20 adapter. This supports one shared base evaluation |
| Replication | Two paired training seeds, 742101 and 742102, govern the declared training sampling schedules; two arms per seed. Within each pair, identical initial adapter, zero-step Adam and RNG state, with recorded hashes |
| Control | 20 updates on the original depth 3–6 planning distribution: alternate depth pairs (3,4), (5,6), repeated ten times |
| Treatment | Updates 1–10 each use depth pair (1,2); updates 11–20 use the same depth pairs and initial scenarios as control updates 11–20 |
| Rollouts | Two independent fresh scenario families per update; 40 episodes per run, 160 total. Last ten updates use the same scenario schedule across paired arms. No replacement of failures |
| Objective | Same terminal verified-goal reward (0/1) and independent-episode LOO. Planning internal weight 1 with a separate global loss multiplier 0.24 applied to policy, entropy and KL; learning rate 2e−5, entropy coefficient 0.01, KL coefficient 0.02, PPO clip 0.2, gradient clip 1, one attempted Adam step per cohort |
| Execution | Same physical one-row exact-context forwards, logical batch 8/microbatch 2, maximum lag 1, and unchanged full-vector tolerance 0.002; 12-turn episode cap |
| Evaluation | A single untouched set of 64 new families, sixteen at each original depth 3–6; shared base plus four final policies = 320 episodes. Same evaluation action/menu seeds per family; no endpoint selection |
| Data separation | Exclude every historical calibration/train/evaluation family, plus the new screen families. Keep each run's training families unique and separate training families across the two training seeds; paired-arm reuse is declared. Freeze all split manifests before inference |

Only the training depth schedule differs between arms. Keep reward, baseline, interface, optimizer, entropy, opponent setup, and evaluation difficulty fixed. Each arm produces fresh trajectories under its own evolving policy, with matched action/menu seed schedules; no trajectory is copied between arms. The original planning wrapper hard-codes depths 3–6, so the easy schedule requires a separately named version with an explicit depth input; never patch the frozen wrapper. The policy validator also requires environment weights to sum to one, which is why the 0.24 scaling is specified as a separate global multiplier applied identically in both arms. This is a new controlled task-specific study, not a literal replication of the shared-gradient run. Validate exact shortest depths, sufficient unique families, and family separation locally before inference. Witnesses and solver outputs remain audit-only. The number of episodes and attempted updates is matched, and both arms have the same maximum action allowance; realized actions and wall time will differ when an episode finishes earlier. Report those differences rather than calling compute exactly equal.

## What to defer

Do not simultaneously increase model size, learning rate, number of updates, add shaping rewards, switch to thinking, change action weighting, or add stronger opponents. Each would blur the result of the first test. A same-scenario baseline comparison is a reasonable separate variance experiment; current data cannot estimate its benefit because the original training scenarios were sampled once. An opponent-mixture experiment is appropriate for market and maze, and coding needs explicit investigation of testing/submission and destructive edits. These are follow-ups conditional on the diagnostic, not part of this $90 proposal.

The guard/billing reconciliation remains independent. Empty inventory does not resolve the original unknown creation, and posted usage is not settled billing. All $125 original training/unknown-guard and $4 recovery allowances remain held. This diagnosis changes no budget or monitor state.
